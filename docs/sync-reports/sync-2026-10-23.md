## Skills Updated

### brainstorm (feeds into spex:brainstorm command)
**Status**: ✅ Evaluated and adapted

**Upstream changes identified** (7.0.0 rebuild, 7.0.1 retune):

Upstream rewrote `skills/brainstorming/SKILL.md` from scratch (539 lines changed). The skill is now organised around drawing out what the user wants and why before anything is proposed:

- **First: what do you actually know?** A private check that routes trivial requests straight to doing them.
- **Look before you ask.** In an existing project, read what the user referred to and the code it connects to before the first message. Never ask what the context already answers.
- **Your first message.** When the user has already said what they want: about 200 words that echo the request back, add what was found, flag constraints or cheaper paths, invite corrections, then one question about the thing the request leaves open. When they have not: one open question with the reason for asking. The offer to skip the questions appears only when the skill started on its own (7.0.1).
- **The conversation.** One question per message as a single sentence, no example-answer lists. Open questions first, menus only when stuck. Questions grounded in the project and prior answers, Socratic, saying what the answer would change. "Ground to cover" as territory (kind of thing, why now, goals/non-goals/anti-goals, prior art, current state, details), never read out as questions. "How it gets made": find out which platform/language/library choices the user wants to own; defaults said out loud and marked as the agent's call. Offer recon. Lay out the approaches in a message of their own, drop the weak ones, recommend one, handle the one-sensible-way case. Show don't tell (visual companion). Spike to feel things out.
- **Play it back** in 200-300 word chunks as each part is understood, alternating with questions. Only what they said goes in as theirs.
- **Size the work** (small change in chat vs. project with full design doc) replaces the 6.3 three-path router.
- **The written design** with intent, goals/non-goals/anti-goals, constraints, approaches, decided how-parts, what is left to the builder. A **builder check** subagent replaces the spec-document reviewer.
- A shorter HARD-GATE with two exceptions (opt-out, approved spike), and a new **Red Flags** table.

**Adapted into `extensions/spex/commands/speckit.spex.brainstorm.md`**:

- HARD-GATE: reading and exploring the project are stated as fine and expected.
- Checklist steps 5 and 6 and the process flow graph: "Ask clarifying questions (play back as you go)" and "Lay out 2-3 approaches".
- Understanding the idea: added "look before you ask" (read what the user pointed at and the code it connects to; never ask what the context answers), the first-message pattern (echo back or one open question with its reason; no skip offer because spex brainstorm is always invoked explicitly), the conversation rules (one sentence per question, open questions first, menus only when stuck, questions grounded in project and prior answers, plain language, ground to cover, how it gets made, offer recon), and incremental playback replacing the single "write back your understanding" step from 6.4.1.
- Laying out the approaches: message of their own, generate several and drop the weak ones (including any that work against the why or that the project rules out), recommend one, one-sensible-way case, approach-level not implementation-level.
- Reaching agreement: approval covers what was shown.
- Brainstorm document structure: Problem Framing now carries success criteria, non-goals and anti-goals; Key Requirements holds user-owned how-choices as constraints and marks proposals as the agent's call with the reason.
- Key Principles: "Multiple choice preferred" replaced by "Open questions first"; added "Look before you ask" and "Say your defaults out loud".
- New Red Flags table adapted from upstream 7.0 (menus steer, read the context, say defaults out loud, approaches before the document, approval covers what was shown, always write the document).
- Example Flow rewritten: open questions and a playback chunk instead of lettered A/B/C/D menus for clarifying questions. The next-steps and oversight choices stay as interactive choices.

**Behavioral change to be aware of**: clarifying questions default to open questions, not multiple choice. This follows the headline change of the upstream rebuild ("options steer"). Interactive choices remain for process decisions (inbox seeds, revisit, next steps, oversight, issue creation).
